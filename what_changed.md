## Browser compile boundary fixed

Shared file-import source previously directly depended on `dart:io`, which cannot compile for Web.

The bounded reader is now split into:

- `lib/core/utils/bounded_file_reader.dart` — conditional facade.
- `lib/core/utils/bounded_file_reader_io.dart` — native `dart:io` implementation.
- `lib/core/utils/bounded_file_reader_stub.dart` — browser/non-IO unsupported-path implementation.

The native implementation retains reported-length and cumulative-stream-length checks. The browser implementation never pretends a fake native path can be opened.

The browser stub was additionally fixed so its `Future` fails asynchronously rather than throwing before callers can await/test the Future contract.

## Browser imports are stream-first and size-bounded

`FileTransferService` now has platform-appropriate acquisition behavior.

Native targets:

- `withData: false`.
- Use the picker-provided cached path.
- Read incrementally with `BoundedFileReader`.
- Validate both reported and accumulated bytes.

Web:

- `withData: false`.
- `withReadStream: true`.
- Validate picker-reported `PlatformFile.size` before consuming data.
- Accumulate streamed chunks only while cumulative byte validation succeeds.
- Continue to validate an in-memory value if a provider/plugin returns one despite the stream-first request.
- Decode UTF-8 / parse Markdown or JSON only after byte validation.

Limits remain:

- Markdown/text: **16 MiB**.
- JSON backup: **64 MiB**.

This late stream-first adjustment intentionally avoids relying on `file_picker`'s eager Web byte-loading default for NoteNest imports.

## Drift Web worker/WASM pairing is reproducible

`tool/bootstrap_platforms.py` now generates all six runners:

```text
android,ios,linux,macos,windows,web
```

For Web it additionally:

1. Reads the direct `drift:` version from `pubspec.yaml`.
2. Requires it to equal the reviewed `DRIFT_WEB_VERSION = "2.34.3"`.
3. Downloads `sqlite3.wasm` and `drift_worker.js` from the matching Drift release.
4. Rejects unexpectedly small downloads.
5. Verifies the WebAssembly header on `sqlite3.wasm`.
6. Rejects a worker response that looks like an HTML error page.
7. Writes those files into the generated Web runner.
8. Fails if Drift is upgraded without explicitly reviewing the Web runtime pair.

Existing Android/iOS fail-fast patch validation remains.

This is package-version/runtime pairing and basic payload sanity, not a claim of cryptographic provenance.

Commit:

- `256ea5d0386b3a7ebfc842e3e9441650e65ca584` — `feat: bootstrap verified Flutter web database assets`

## App lock now models real platform capability

The current `local_auth` package does not implement every NoteNest target. Instead of importing/assuming it universally, NoteNest now has:

- `lib/services/app_lock_service.dart` — conditional facade.
- `lib/services/app_lock_service_io.dart` — native wrapper.
- `lib/services/app_lock_service_stub.dart` — browser/non-IO unavailable implementation.

The native wrapper converts missing-plugin/platform/authentication failures to safe unavailable/failed results.

The root lock gate now calls `canAuthenticate()` before authentication. A stale persisted `appLockEnabled=true` value therefore cannot permanently trap Web/Linux behind an impossible unlock screen.

Settings now checks capability, explains unavailable state, prevents unsupported enablement, and still lets an already-enabled stale preference be disabled.

No custom browser/Linux password system or home-grown biometric mechanism was added merely to advertise parity.
